The MCP adapter connects to IPv4 loopback `127.0.0.1:61172`. One UTF-8 JSON request and one JSON response per TCP connection, each terminated by newline. This is internal transport, not an extra agent orchestration protocol. No automatic retries. Requests and responses are limited to 1 MiB.

The TCP endpoint is unauthenticated. Any local process able to connect can invoke tools; use only in a trusted local environment and never expose or forward this port to a network. Context tokens and target guards are not authentication.

Request:

```json
{"id":"client-generated-unique-id","method":"status","params":{},"timeoutMs":5000}
```

`id` is a nonempty string (maximum 128 characters), `method` a known method, `params` an object, `timeoutMs` an integer from 100 through 10000. Missing timeout defaults to 5000. Reject invalid input before scheduling work. The host adapter checks the monotonic deadline immediately before each mutation, including deferred callbacks. A dispatched host action cannot necessarily be cancelled.

Response:

```json
{"id":"client-generated-unique-id","result":{"status":"observed"}}
```

or

```json
{"id":"client-generated-unique-id","error":{"code":"deadline_exceeded","message":"Outcome unknown; inspect state before issuing another write.","outcome":"unknown"}}
```

The client checks response correlation. Errors after dispatch or a lost connection must not become an automatic replay. `id` correlates requests; it is not a persistent deduplication key. A result describes actual observation/verification scope, not universal success.

MCP returns the same envelope as both `structuredContent` and JSON text. Text uses compact separators without dropping values, nulls, error outcomes or verification fields; whitespace is not a protocol contract. The toolkit does not route to the GUI automatically. An agent may explicitly use Computer Use for unsupported operations, but must inspect uncertain writes rather than blindly repeat them through another interface.

Version `0.2.0` uses MCP SDK 2.3+. Expected bridge and argument-validation failures remain error-flagged tool results with the envelopes above. An unexpected uncaught adapter exception instead surfaces as an MCP JSON-RPC error under SDK 2, not a fabricated tool result or `not_dispatched` acknowledgement. Such a protocol error is not permission to retry: the host operation may already have run.

The registry exposes45 methods, including ten `grid.*` and three read-only `modulators.*` methods, across discovery, flat and one-hop layer direct parameters, Actions, transport, tracks, devices/Remote Controls, launcher, MIDI and version-gated Grid inspection/scalar and boolean-panel writes/module insertion/move/selective delete/raw custom-name CAS/single-input cable editing. Existing request shapes remain unchanged. `capabilities` describes implemented domains and limits, not host acceptance. `bitwig-agent-rpc list` and `describe METHOD` expose the Python registry offline; the Java/MCP fixture checks transported schemas against the host registry. This is not complete Bitwig interface coverage.

Java transport boundary (Gson): `RpcServer.Handler.handle(String method, JsonObject params, long deadlineNanos)` returns `CompletableFuture<JsonObject>` containing the **result** object. Handler must enqueue work for the host and never call host model APIs from the network thread. Transport does not implement retries, host state, selection or business logic. Transport errors are envelopes; host method rejections may complete exceptionally using the shared `RpcException` type carrying `code`, `outcome`, and message.

## Core discovery and direct parameters

Parameter objects accept exactly the listed keys; extra keys and explicit nulls are rejected. Unless a narrower bound is documented, strings must be nonempty and at most4096 UTF-16 code units. `trackId` is a UUID reported by the current track bank, not a name. Root `deviceIndex` is an integer0–15; general paging is not implemented. The separate one-layer API below does not reinterpret flat device indices. MCP/CLI `timeoutMs` is removed from method params and sent in the transport envelope.

| Method | Exact params |
|---|---|
| `status` | `{}` |
| `tracks.list` | `{}` |
| `devices.list` | `{"trackId":"..."}` |
| `parameters.list` | `{"trackId":"...","deviceIndex":0,"expectedDeviceName":"..."}` |
| `parameters.set` | `{"trackId":"...","deviceIndex":0,"expectedDeviceName":"...","contextToken":"...","parameterId":"...","value":0.5}` |

`status` returns `status:"observed"`, `hostVersion`, `apiVersion`, `projectName`, `engineActive`, `playing`, the two window capacities, and `parameterBindingDiagnostics`. Diagnostics report the current bank target, match/established state, source-local ID callback counters, cache generation and observed-proxy identity scope; when unbound, only established/identity scope are present. They are not a complete callback event trace. Status is a snapshot, not a project identity or host-test certificate.

`tracks.list` returns `tracks:[{trackId,index,name}]`, `scope:"flat_track_bank"`, and `window:{offset,capacity,total,complete}`. `devices.list` returns `trackId`, `devices:[{deviceIndex,name,type}]`, `scope:"top_level"`, and the same window metadata. Both windows have capacity 16. `complete` describes the bank's count/window coverage only, not all project object types. A track or device outside the current window is rejected rather than silently selecting another target.

`parameters.list` binds a target within the existing track/device banks and returns `status:"observed"`, `target:{trackId,deviceIndex,deviceName,contextToken}`, `parameters:[{id,name,normalizedValue,readable}]`, `scope:"host_exposed_direct_parameters"`, and `identityScope:"observed_bank_proxy_context_not_persistent_device_identity"`. An unknown or inaccessible value is JSON null, not zero; names may initially be empty. Each fixed bank proxy continuously observes its own IDs/names/values; binding does not clear those observations or require unchanged IDs to replay. Parameter maps are allocated lazily. Copy `target.deviceName` into `expectedDeviceName` when writing. The token belongs to the observed context and process, not a durable device UUID. Rebinding and observed context/ID changes invalidate its token. A metadata-only name change retains that proxy's observations while invalidating the token; observed existence, track UUID or position changes evict the source cache. Replacement at the same track/position without an observable existence transition cannot be distinguished from the same proxy, even if its name changes; retained values may then be stale. Initial callback ordering and bank-shift recovery have not been established for all transitions. Re-enumerate after edits; this is not a persistent-device identity guarantee.

`parameters.set` requires the current context token, unchanged target, an ID from that context and a readable parameter. It never implicitly rebinds a stale target. `value` is finite and normalized to [0,1]; the host call uses resolution 16384, rounding to its 16383 intervals. Results include `target`, `parameterId`, `requestedValue`, `appliedValue`, `observedValue`, `difference`, `tolerance`, `matchesRequested`, `verification` and `resolution`.

The result is `status:"observed"` only when the target still matches and either the value was already within tolerance (`verification:"already_at_value"`, no write dispatched), or a subsequent callback from that same bank proxy matches (`"observer_after_write"`). Otherwise it is `status:"dispatched"`, with `verification:"readback_mismatch"` or `"not_observed"`; a stale pre-write cache or another source's callback is never returned as post-write evidence. Observation is bounded to roughly 750 ms and the request deadline. This is not an atomic transaction, persistent save verification, or proof that another actor did not write the same value. Observers are asynchronous; a context token is not a cross-tool lock.

Business errors include `invalid_params`, `not_ready`, `outside_window`, `stale_target`, `stale_context`, `unknown_parameter`, `busy`, `unavailable`, and `deadline_exceeded`. Errors before parameter dispatch have `outcome:"not_applied"`; a deadline or target change after dispatch has `outcome:"unknown"`. A request ID is not an idempotency key. No automatic retry or GUI fallback is implemented.

### One-hop layer devices

`parent` is the shared `DeviceParent` schema, exactly `{"trackId":"<observed UUID>","deviceIndex":0,"expectedDeviceName":"<current root name>"}`. It always addresses a top-level device. Layer and child indices are not substituted into this root address. The same shape is used by read-only modulator methods; this shared schema does not extend layer traversal or change existing layer wire semantics.

| Method | Exact params |
|---|---|
| `devices.layers.list` | `{"parent":{...}}` |
| `parameters.layer.list` | `{"parent":{...},"layerId":"<observed UUID>","childDeviceIndex":0,"expectedChildDeviceName":"<current child name>","discoveryToken":"<from discovery>"}` |
| `parameters.layer.set` | The same child address plus `contextToken`, `parameterId`, and finite normalized `value` in0–1 |

Discovery returns the actual `parent`, `scope:"one_layer_hop"`, an observed layer `window`, and `layers`. Each layer carries `index`, `layerId`, `name`, `channelIndex`, `readiness`, its child `window`, and `devices`. Each child carries `index`, observed `childDeviceIndex`, `name`, `type`, `readiness` and `directContextAvailable`; only eligible contexts receive a `discoveryToken`. Windows expose nullable `offset`, `total`, `exists`, fixed `capacity`, `complete` and `readiness`. Unknown is not zero or empty. A parent without layer support rejects `unsupported_scope`; an unobserved/invalid window rejects `not_ready`.

Banks are created only at initialization: two layers per root, two children per layer, fixed zero-offset nested windows. Both parent and child must fall within observed counts. `childDeviceIndex` accepts only0–1. There is no deeper traversal, pad/slot target, nested Remote Control, private Grid-module target or paging fallback. Child-to-layer ownership follows construction of that layer's device bank, not a dynamic equality observer: native6.1.3 rejects an equality value for proxies that always refer to the same target. This is not persistent physical-device identity.

Copy the discovered child address into `parameters.layer.list`. Its `target` retains the same nested address and adds a `contextToken`; use that complete target plus `parameterId`/`value` for the write. Normalization, quantization and fresh same-source acknowledgement follow the flat parameter contract above. Discovery neither selects a device nor changes the active parameter binding. Flat and nested parameter operations share one active binding and pending request: switching targets invalidates the old binding token, while continuously observed per-source data survives request A→B→A without ID replay.

Discovery readiness does not mean parameter IDs/values have arrived. Nested data is admitted only with observed ancestry, including a nonnegative assigned track position and an assignment-aware layer channel index; ordinary proxy default zero is not assignment evidence. The integer observer reports unassignment as−1, without getter fallback or callback replay. Rejected initial callbacks are not resurrected from getters. Name changes invalidate tokens but preserve continuous data. Known discontinuities—including conservative ancestor/window and assigned channel-index changes—retire nested direct access for the extension lifetime; subsequent callbacks do not establish provenance. `channelIndex` is not the layer-bank slot, and a change is not proof of physical replacement: project-order renumbering may also close access conservatively. The response reports `physical_rebind_callback_provenance_unavailable_until_extension_reload`. Reload is a new observation lifetime, not an automatic retry or proof that the previous write failed. Unobserved same-metadata physical replacement remains undetectable. The existing root getter-snapshot admission policy is separate.

Layer discovery and parameter observations do not establish native write isolation, DSP, whole-hierarchy coverage or general persistence. See [coverage limits](VERIFICATION.md#coverage-limits-and-unresolved-results).


## Host Actions

`actions.list` accepts exactly `{}` and returns `{status:"observed",scope:"host_action_catalog",actions:[{actionId,name,category:{id,name}|null}]}` from `Application.getActions()` and the Action metadata. These are the host's current IDs and localized names, not guessed command names. Catalog membership does not establish enablement or completion in the current UI context.

`actions.invoke` accepts exactly `{"actionId":"..."}` (the same nonempty, maximum 4096-character string rule) and resolves it using `Application.getAction(id)`. An absent ID is rejected with `unknown_action`, `outcome:"not_applied"`. The lookup and invocation run on the host thread; the deadline is checked again immediately before invocation. A returned call reports only `{status:"dispatched",actionId,completion:"not_observed"}`. Actions may depend on selection/focus, open dialogs or change a project. A dispatched save/export Action is not proof of a written file. Observe the resulting state explicitly; no retries, completion polling, selection routing or GUI fallback are added. MCP exposes `timeoutMs` separately, as for the existing methods.

## Domain controls

`T` below means `trackId`; `D` means `trackId`, `deviceIndex`, `expectedDeviceName`. These abbreviations describe the contract only: requests use full field names. Required keys are listed first; “optional” keys are omitted unless requested, never filled with implicit mutation defaults. Schemas and runnable examples are available through `bitwig-agent-rpc describe METHOD`.

| `transport.get` | `{}`; observed `projectName`, transport and recording/automation flags |
| `transport.set` | At least one optional `playing`, `tempoBpm`, `positionBeats`, `metronome`, `loopEnabled`, `loopStartBeats`, `loopDurationBeats` |

| `launcher.list` | `T`; sixteen slots, including empties and observed playback/recording states |
| `launcher.create` | `T`, `slotIndex` (0–15), `lengthBeats` (integer 1–4096), `name` (1–128 UTF-16 units); empty slots only |
| `launcher.import` | `T`, `slotIndex` (0–15), absolute normalized local `path`; readable regular file, empty slot only, never overwrite |
| `launcher.launch` | `T`, `slotIndex`; queued and actually playing are distinct |
| `launcher.stop` | `T`; stop launcher clips on that track |
| `notes.read` | Explicit MIDI window below |
| `notes.edit` | Explicit MIDI window plus `edits` (1–256 entries) |

Transport uses raw BPM and quarter-note beats. Tempo 20–666 is a toolkit-supported range evidenced by a shipped controller, not a claim about every native raw limit. Position/loop start are nonnegative; duration is positive; their sum must remain finite. Recording/arranger automation/launcher automation write flags are read-only. While enabled, non-stop transport mutations are rejected; explicit stop remains available. Multi-field mutations are not transactions: each field is guarded and separately verified, and earlier changes can remain when a later field fails.

When an explicit `playing:false` accompanies other transport fields, the bridge waits for the stopped-state observation before dispatching those remaining fields, within the same bounded observation window. Sending stop and seek consecutively is not sufficient: an asynchronous stop can overwrite the requested position. Deferred writes still recheck cancellation, deadlines and recording/automation guards. A missing stop observation leaves remaining fields `not_dispatched`; partial or unknown completion still stops the caller rather than triggering a retry.

Both transport reads and write-result snapshots include `projectName` from the existing interested Application source. This lets callers check the expected project label and safety flags in one response instead of pairing `status` with `transport.get`. A null, missing or changed name is not permission to mutate. This is an observed name, not full-file-path identity, an atomic snapshot across fields or a project lock.

Track volume, pan and remote control values are normalized [0,1]; accompanying host display strings are not interchangeable numeric units. Track creation rejects an incomplete initial UUID/index/type window before invoking a factory. An already-observed grouped baseline rejects `unsupported_scope/not_applied` before any factory or creation quarantine: true grouped insertion remains unsupported. After one supported factory call, attribution requires a complete after-window, one new UUID, matching type/position and repeated observations before assigning a name. A group appearing after dispatch or concurrent unrelated creation can still leave an unnamed created track with an unknown result. An unresolved dispatched creation blocks further factories; inspect the actual project rather than retrying.

Mix observations belong to continuously interested bank proxies. An established UUID/existence change invalidates operation generations and masks reads/writes until an actual controller `flush` refreshes previously observed getters with matching identity/existence. This is not an atomic physical-track snapshot. Readable getter baselines do not make prior-generation equality a verified no-op: a post-rebind same-value write can remain `unknown` if the host emits no fresh callback. Agents should submit only fields that differ from a fresh readable `tracks.get` snapshot; inspect overall completion and each field's verification, and never automatically retry an unknown composite result. Legacy selection can remain unreadable until a current-generation selection callback. Old operations never regain validity after same-UUID reappearance.

`tracks.select` is an explicit UI-navigation command, not a verified mix-field setter. Like `devices.select`, it returns `status:"dispatched"`, `completion:"not_observed"` and `verification:"selection_has_no_reliable_public_observer"`. It dispatches once even when a cached selection value is already true; that value cannot prove the requested editor navigation. Its snapshot can still contain `selected:null` after a project/proxy rebind, and it has no setter-style `fields` or `matchesRequested` acknowledgement. Inspect the actual track/device context and any selection-triggered arming before dependent edits. UUID/rebind, cancellation and deadline guards remain active; an error after dispatch can still be `unknown` and must stop the caller. A dispatch-only receipt is not permission to repeat the command blindly.

Explicit normalized volume, pan and Remote Control mutations use the native `setImmediately` API: absolute RPC values must not wait for physical-controller pickup. Global takeover preferences are untouched. Remote value writes additionally reject active or unobserved recording/automation-write modes immediately before dispatch.

Device insertion requires the expected count and complete top-level window. Confirmation observes a fresh appended device, a count delta and unchanged prefix; `requestedIdentifierVerified:false` explicitly distinguishes that observation from proof of the requested plug-in/preset identity. File insertion passes the path to the native host API, not a shell. `devices.catalog` checks local factory Grid file presence; insertion and rendered musical identity need separate native evidence. Community website UUIDs are not advertised as native device IDs.

Remote tokens bind observed track/device/page/control metadata, not persistent physical devices or invisible same-name remappings. Observed lifecycle changes mask affected controls until actual host flush reconciles current previously observed getters; subscription history is retained because unchanged callbacks may not replay. Absent/remapping controls and never-observed/nonfinite getters remain unavailable. Flush refreshes page comparison baselines but never advances write acknowledgement sequences or freshness. Thus a recovered same-value request can dispatch and remain unacknowledged rather than claim a verified no-op. Old tokens and pending operations do not regain validity. Neither remote nor direct parameter controls expose Grid module creation/cables.

`launcher.launch` and `launcher.stop` report `completion:"observed"` when the requested playing/stopped state is observed. A confirmed queue reports `status:"dispatched"`, `playbackState:"queued"` and `completion:"not_observed"`: accept this only as an explicitly expected dispatch-only result, then independently inspect `launcher.list` for actual playback/stop before dependent edits. If neither the desired state nor a queue is observed within the bounded observation window, `completion:"unknown"` requires stopping the writer, not retrying. These are launcher-state observations, not musical/audio completion or cancellation guarantees.

`launcher.import` shares the launcher mutation/cursor lease, checks the explicit slot is empty immediately before `replaceInsertionPoint().insertFile`, and requires a fresh observed content transition. The result reports `verification:"slot_content_transition"` and `requestedFileVerified:false`: it does not prove file identity, decoding or audible output. Unsupported native content may silently do nothing; an unobserved dispatched import returns `import_not_observed/unknown`, never a retry. The SDK has no atomic conditional insertion; an external edit after the final occupancy check remains a race.

Unresolved dispatched launcher creation/import stays quarantined beyond the RPC future's lifetime. Conflicting creation, import and note writes reject with `unresolved_mutation/not_applied`; inspection remains available. Only normal positively observed completion releases the target. Late callbacks, an empty observation or elapsed time do not clear an ambiguous result. The affected UUID/slot and original bank proxy remain quarantined for the extension instance. Recreating the extension clears this in-memory guard but does not cancel or establish completion of pending native work: inspect and settle host state before using that reset boundary.

### MIDI window and edits

Every `notes.read/edit` request supplies `trackId`, `slotIndex`, `channel` (0–15), `stepSizeBeats` (1/128–4), `startStep` (0–1048576), `steps` (1–128), `pitchStart` (0–127), `pitchCount` (1–128; range must end at or below 128). MIDI numbers avoid octave-label conventions: 60 means the same pitch even when the UI calls it C3 rather than C4.

Each edit is either `{"op":"set","beat":0,"pitch":60,"velocity":90,"durationBeats":1}` or `{"op":"clear","beat":0,"pitch":60}`. Velocity is an integer 1–127, duration 1/128–4096 beats. Beat and duration must align exactly to the requested step grid. Set duration must fit the requested window and observed loop end. Duplicate cells, overlapping same-pitch sets, existing onset collisions and edits starting inside a sustain are rejected before note writes. Clearing an obstructing note requires an explicit earlier call; there is no whole-clip replacement.

`launcher.create`, `notes.read` and `notes.edit` explicitly select the launcher clip in the UI. They bind the cursor using slot-proxy equality and track UUID, with a local cursor-operation lease; no name fallback. This can affect host auto-arm/editor selection according to existing preferences. These calls do not silently change preferences.

Selection itself counts as dispatch, including for `notes.read`: a later context change, deadline or host failure reports `outcome:"unknown"` even when no note was written. `not_applied` must not imply that an already-dispatched selection had no UI or auto-arm side effect. A failed read is therefore not automatically safe to retry.

Readback reports actual `NoteStep` state, velocity normalized to [0,1], duration and grid-cell onset. The public API does not establish exact sub-step onsets or multiple onsets within a cell. Results always report `completeClip:false`. Dense reads return at most 2048 onset objects, with `notesInWindow`, `notesReturned`, `completeWindow` and subdivision guidance; changed-cell verification remains separately reported for every requested edit. This is not a lossless arbitrary-MIDI exporter. A successfully dispatched cursor operation is not proof of audio-clip suitability, saved persistence or audible output.

Grid reconfiguration has a separate unresolved readiness limit: the installed API exposes setters but no acknowledged current step-size/scroll-offset revision. Configuration follows observed cursor identity, then waits 150 ms to cover the observed 6.1.3 100 ms grid-refresh debounce plus a delivery margin. Results expose `gridSettleMs`, `gridReadiness:"scheduled_settling_not_acknowledged"` and `gridGeneration`, not a data barrier. Generation scoping rejects known old/unsettled observations, but a late same-cell callback has no source-window ID. A cold first-read regression previously returned beat 1 for a note the native Inspector placed at beat 2. The correction does not retroactively pass the original preservation criterion or guarantee arbitrary delayed callback delivery. Alternating-window/step-size and independent native E2E remain separate evidence; consumers must not treat grid readback as atomic or lossless. See [coverage limits](VERIFICATION.md#coverage-limits-and-unresolved-results).

### Read-only primary modulators

These three methods use the same generic strict catalog, CLI, MCP and JSON transport. They require no selection, direct-parameter binding, context token or Grid write authorization.

| Method | Exact params |
|---|---|
| `modulators.capabilities` | `{}` |
| `modulators.list` | Required `parent:DeviceParent`; optional integer `offset`0–100000 (default0), integer `limit`1–128 (default64) |
| `modulators.parameters.get` | Required `parent:DeviceParent`, canonical current UUID `modulatorId`, exact string `parameterId` of0–1024 UTF-16 units |

`DeviceParent` has exactly canonical UUID `trackId`, integer `deviceIndex`0–15 and nonempty `expectedDeviceName` of at most4096 UTF-16 units. UUID hex case is accepted, shortened syntax is not. Extra keys, explicit nulls, numeric strings, boolean-as-integer values and decimal/exponent integer tokens reject `invalid_params` before scheduling. Empty `parameterId` is valid only when it identifies a unique direct child; identifiers are case-sensitive and never trimmed. `timeoutMs` remains the standard client/envelope option, not a method param.

Discover `trackId` with `tracks.list`, then the root index/name with `devices.list`. Pass that observed address as `parent` to `modulators.list`, choose a row and its supported descriptor, and pass its **current** `modulatorId` and exact `parameterId` to `modulators.parameters.get`. Neither type UUID, raw/custom name, row index nor display label is an alias. Reacquire current UUIDs after reopening or identity changes: the native UUID can change even on the same object. Use `bitwig-agent-rpc describe modulators.list` and `describe modulators.parameters.get` for offline request examples; examples are not live identities.

Capabilities report the exact6.1.4 loaded-JAR `runtimeGate`, independent `discovery` and `stringPanelRead` objects (`available`, nullable `reason`). Top-level `available` requires runtime and discovery; `parameterReadAvailable` additionally requires the string binding. String-binding failure does not disable inventory, nor do Grid-specific binding failures determine modulator availability. `writeAvailable:false`, `nativeMutation:false` and `nativeVerification:"not_established_by_binding"` are explicit. No supported binding establishes reachable-instance, DSP, GUI or persistence acceptance.

Inventory has observed completion, `parent`, `target`, `scope:"primary_modulators_on_root_device"`, `window:{offset,limit,total,returned}`, `modulators`, `complete` and explicit `coverage`. Only the primary collection is included; secondary/nested modulators, nested components, mappings and destinations are excluded. Every primary member's object/current UUID/order and ownership are checked before and after capture; names, contents and direct-child descriptors are inspected only for the requested page. Pagination is independent observations, not a revision-consistent cursor. An offset beyond the current total returns an empty page, not evidence of an empty collection.

Each row has `index`, current `modulatorId`, raw `name`/`customName` (nullable when absent), `contentsAvailable`, `contentState`, `typeId` and `parameters`. Nonloading access returns unmaterialized contents honestly: `contentsAvailable:false`, `contentState:"unmaterialized"`, `typeId:null`, `parameters:null`; no loader, restore or materialization fallback is called. Materialized contents expose direct-child descriptors with `parameterId` (null when not addressable), `modelClass`, `supported`, and nullable `kind`/`controlFamily`. An exact native string panel with an available reader reports `supported:true`, `kind:"string"`, `controlFamily:"string_panel"`. Other children remain explicit unsupported descriptors; inventory never reads their values or string-panel values. `complete` is false for pagination, unavailable contents or unsupported children; even true covers only this bounded primary/direct scope.

The single-parameter result returns current `modulatorId`, `typeId`, exact `parameterId`, `kind:"string"`, `controlFamily:"string_panel"` and the raw native String `value`. Root targeting uses public observed index/name and native owning-track corroboration, not persistent physical-device identity. Owning project/context checks are not application's active-project identity; unobserved same-metadata replacements, native ABA, atomic model snapshots and cross-page consistency are not guaranteed. There are no modulator setters, creation, mappings, destinations or automatic GUI fallback.

Prior 6.1.3 native coverage was limited to materialized primary Macro string panels. Those observations do not establish 6.1.4 instance coverage, unmaterialized contents, DSP/Undo/MIDI/write or whole-toolkit acceptance. ### Version-gated Grid controls

`grid.capabilities`, `grid.catalog`, `grid.get` and `grid.parameters.get` are private read-only Grid methods. Their schemas come from the same strict Python catalog used by CLI and MCP: extra fields, explicit nulls, numeric strings and boolean-as-integer values are rejected. The standard client `timeoutMs` option remains envelope metadata, not a Grid parameter. No implicit selected-device target is accepted.

The `0.2.0` native compatibility gate accepts only Bitwig **6.1.4** with loaded host JAR SHA-256 `77a50264156a9f79c925fa85e0456720ce157bfa10e2503d6049e2f733af4ba6`; the older `0.1.2` release retains its separate 6.1.3 gate. Matching a filename or an unrelated installed JAR is insufficient. `grid.capabilities` reports the actual gate/binding result and separates catalog, structure and typed-parameter coverage; it does not promise full coverage merely because the host version matches. Unsupported or unresolved bindings fail closed rather than trying guessed reflection names, GUI selection, installation or automatic fallback.

`grid.catalog` filters native MODULE names by case-insensitive substring and returns deterministically ordered `{typeId, name}` entries with a `window` reporting `total`, `offset`, `limit` and `complete`. An empty query includes all mapped MODULE entries; it is not a device/preset catalog. Type UUIDs identify module types, not instances in a patch. `devices.catalog` remains the separate factory-device file discovery API.

`grid.get` reuses the explicit device target: obtain `trackId` from `tracks.list`, then `deviceIndex` (0–15) and exact `expectedDeviceName` from `devices.list`. For example, the following JSON has a valid shape but its UUID must be replaced with a discovered live track:

```json
{"trackId":"12345678-1234-1234-1234-123456789abc","deviceIndex":0,"expectedDeviceName":"Poly Grid","moduleOffset":0,"moduleLimit":32,"includeParameters":false}
```

For layout, wiring and module naming, use the structure-only example above. Discover parameter IDs with a small parameter-including page only when needed, then refresh the exact control with `grid.parameters.get` before a parameter CAS write. This avoids repeatedly returning unrelated controls; it does not change the `includeParameters:true` wire default or make several pages atomic.

The result includes target metadata, modules, connections, a bounded window and explicit coverage/identity limitations. Read instance UUIDs, catalog type UUIDs and list-local keys as separate identities. Native instance UUIDs are not persistent: all seven observed module UUIDs changed on same-process project reopen while types, positions, ports, typed values and stored topology matched. Reacquire identifiers after reopening; labels and list-local keys are not substitutes for persistent identity. Unknown model types, unsupported parameter fields and excluded pages must not be interpreted as a complete graph. `includeParameters=false` requests structure without parameter values. A sequence of pages is not an atomic snapshot and no native revision is fabricated.

`window.complete` means the module page covers the current module window. Top-level `complete` additionally requires no recorded unsupported coverage: a structure-only read intentionally has `complete:false` with `parameters_not_requested`, and a full module page can still report unknown native children. Check the requested coverage and returned structure; do not require top-level `complete:true` merely to use an otherwise complete layout/wiring/name page, or mistake it for lossless native export.

Native path ancestry also changed after group insertion/save/reopen; device-local data survived, but full path strings are not stable identifiers. `target.nativeOwningTrack` reports before/after corroboration: derive the native device's nearest WSA track ancestor, apply the public channel-ID mapping (including kWY's channel alias), and compare its UUID with the requested track before graph traversal and again after capture. Missing ownership/alias/UUID rejects `grid_unavailable`; mismatch rejects `stale_context`. There is no fallback to a name or old public observation. Device position remains `public_observed_only`; this guard does not establish persistent device identity, same-track same-name replacement detection, native ABA detection or cross-request atomicity.

In `grid.get`, modules expose `instanceId`, `localKey`, `typeId`, `x`, `y`, `width`, `height`, input/output ports and optional typed parameters. Footprints use native grid units, not pixels; unavailable dimensions remain null/partial. `name` is the native effective instance name; `customName` is its raw override (empty means no override); `typeName` comes from the catalog type UUID lookup. Ports retain their keys/paths and add native `name`, including disconnected inputs. Typed parameters retain structural `path` and add local/preset `parameterId`, stored `name` and `shortName`. These identifiers and labels are not promised persistent or globally unique. Empty native names remain empty; unavailable metadata is explicit JSON null with a field-specific `unsupported` reason, never a guessed fallback. Parameter `supported` describes the typed observation, not complete metadata coverage.

`device.modelClass`, `graph.modelClass`, module/port `modelClass` and `editContext.ancestorUndoManager.modelClass` expose concrete native runtime classes for compatibility diagnostics. They are not stable public identifiers or permission to mutate.

Float `numericUnit` is the native definition's **unit-kind token**, not a promise that the raw number is already in that unit; use the existing native display string for presentation. Integer `displayPrefix`/`displaySuffix` are native presentation affixes. Neither formatter output nor labels define a reversible numeric-input grammar. Context-dependent/localized UI equivalence is not universally guaranteed. Connections describe **incoming stored links to the returned modules**: each source belongs to the same graph but can lie outside the module page. Therefore an endpoint absent from the current page does not imply a broken cable. Inspect `complete`, `coverage`, `unsupported` and `identityCaveat` alongside `window`.

Connections are **stored native-model links**, not a proven active/audio/note signal graph. Independent native inspection found Note Grid with Enable All Expressions off showing four visible cables while the model retained eight links, including disabled expression paths. The reader does not infer activation from link existence or silently filter these paths. Use the native UI/behavior as a separate oracle until activation metadata is mapped and verified.

`grid.capabilities` exposes `gatePassed`, `available`, `binding` and `runtimeVerification` separately. `catalog`, `structure`, `nativeOwningTrack`, `typedParameters`, `display`, `moduleFootprint`, `moduleNames`, `typeNames`, `parameterNames`, `portNames`, `numericUnits`, `integerDisplayAffixes` and `parameterInspection` describe availability, coverage and binding failures. Native ownership is required for graph reads; failure disables structure/dependents, not the independent catalog. Context bindings gate parameter inspection separately without disabling existing graph reads. Descriptive metadata groups bind independently; missing labels remain null/partial. `grid_unavailable` means a required binding/observation is unavailable, `grid_bounds_exceeded` a traversal bound, and `not_grid` a non-Grid target; do not collapse these into an empty graph. Standard target/readiness/stale-context/deadline errors still apply.

The four read operations use the mapped native document dispatcher with deadline/cancellation and explicit target/ownership checks; they do not mutate the host or select a device. Both application dispatch-thread status and `Q_().isEventDispatchThread()` are checked. `Q_` returns the current scoped executor, not an executor owned by that model; ancestry and UUID checks remain separate. Read coverage does not establish parameter/topology writes or native undo. Insertion and cable writing are separately specified below.

Nonempty FX numeric Remote Controls, native UUID races and the kWY track-alias branch lack comprehensive native coverage. Track scalar/send observations do not establish selection readability after reopen. See [coverage limits](VERIFICATION.md#coverage-limits-and-unresolved-results).

#### Write one Grid parameter

For a supported scalar or boolean panel, read the current `grid.parameters.get` result immediately before writing. Send the same explicit device/module/parameter target, its `parameter.kind` as `expectedKind`, its raw `parameter.value` as `expectedValue`, and the requested raw `value`. String panels are read-only and must not be copied into this write flow. The server independently rebinds and rechecks live context; earlier `editContext` JSON is never authorization.

| Kind | Accepted raw values |
|---|---|
| `boolean` | JSON `true`/`false` only, not0/1 |
| `integer` | Signed32-bit JSON integer tokens, within the actual native range |
| `enum` | Signed32-bit JSON integer tokens matching an actual listed option **value**, not its list position |
| `float` | Finite JSON numbers within native range; integer tokens must be exactly representable as binary64 |

Numeric strings, nulls, booleans-as-numbers, fractional/exponent tokens for integer/enum, nonfinite numbers and silent clamping are rejected. The TCP decoder preserves number lexemes before domain validation. Float fractional/exponent values use finite binary64 conversion; numeric positive/negative zero compare equal. Kind and exact raw-value preconditions precede even a no-op. A mismatch rejects `stale_context`; range/options/type failures reject `invalid_params`.

For scalar controls, the native editor invokes only the exact public final raw controller operation `aLw.UNj(double):void` for mapped rce/Hgx/iS3/Lig/RuU/nhW implementations. Exact Hgx→rXz→rce inheritance is checked; other subclasses are not automatically authorized. It adds no engine-input setter, parser, transaction wrapper, gesture/touch management, lock acquisition, retry or rollback. Live ownership/membership/lifecycle, project/context/default-transaction, thread, license/property, touch/undo and device-lock-owner relations are checked on the document callback before dispatch. The public controller's safely published stopped/nonrecording/nonautomation observations and monotonic epoch also reject observed changes/ABA while queued or completing. This is **observed safety**, not atomic native transport/recording exclusion.

For Hgx controls such as Attenuate VALUE, raw `0.5` means native `50%`, not raw `50`. Bipolar mode changes the live raw minimum; the same descriptor may change in place. Range is reread before dispatch, with no clamping or automatic mode change. A numeric write does not toggle bipolar/STEREOIZE or flatten panel references into a compound value. Changing bipolar mode is a separate native operation that can coerce a negative value to zero.

Results contain the selected actual `parameter`, `previousValue`, `requestedValue`, `mutationDispatched` and `verification` (`exact_native_model_readback` or `already_matched`). A guarded already-matching request never invokes the setter. `nativeMutation`/`nativeUndo` indicate that the undo-aware native controller operation was invoked, not confirmed Undo grouping. Read `nativeUndoScope`, `undoGroupingVerified:false`, `engineAcknowledgement:false` and `safetyScope`; model readback is not DSP acknowledgement. After dispatch, native failure, timeout/cancellation, serialization or late target/safety failure has outcome `unknown`. Inspect actual state before another write.

`grid.capabilities.parameterWrite` is independently gated; unavailable writer bindings do not disable reads. Its `nativeUndoAwareOperation` describes the setter route; it exposes no dedicated Undo command or grouping guarantee. `graphWrites` describes the separately gated insertion, module move/delete/rename and single-input connection surface below, not scalar parameters or full topology editing. The capabilities call itself remains read-only.

Representative scalar observations do not establish all-module write behavior, disabled Note Grid DSP, atomic native transport exclusion or general undo grouping. See [coverage limits](VERIFICATION.md#coverage-limits-and-unresolved-results).

#### Insert one catalog Grid module

`grid.modules.insert` requires exactly `trackId`, `deviceIndex`, `expectedDeviceName`, `typeId`, `x`, `y`. Discover the device target through `tracks.list`/`devices.list` and the canonical MODULE type UUID through `grid.catalog`; UUID hex case is accepted, but shortened UUID syntax, names, instance IDs and arbitrary resource paths are not substitutes. Coordinates are absolute native grid units, not pixels/deltas; decimal/exponent tokens, booleans, strings, nulls and out-of-int32 values reject. There is no implicit selection, default position, batching, automatic connection or retry.

The adapter verifies exactly one matching MODULE catalog entry, resolves its existing resource via native `TL.cfM(UUID):File`, constructs the public unnamed-package adapter, then calls `g2L.cfM(String[],ZuD)`. This normal loader can complete synchronously on a cache hit or asynchronously; parsing/conversion is not a pure read. On delivery, it requires exactly one mapped, detached, nondeleted, unowned module with the requested type and a fresh instance UUID. It rechecks the unchanged destination membership/identity/type/footprints/layout, target/owning-track/project/context, observed stopped/nonrecording/nonautomation epoch, native placement prerequisites and deadline before invoking public `IcG.cfM(Collection,int,int,false,null)`. It does not use the String convenience-placement overload or fabricate a module from catalog metadata.

The destination must contain at most127modules before loading and again before placement, so the inserted graph has at most128. Existing and incoming footprints must be positive; endpoints and prospective maximum-X plus cumulative widths must fit signed32-bit, and the entire occupied Y span must be at most65536 before native placement/layout allocation. Incoming dimensions are checked after loading the real module: a geometric rejection can therefore report `outcome:"unknown"` even though placement never ran. Do not infer `not_applied` from an error message mentioning pre-allocation bounds. These limits are stricter than validating each coordinate independently. ### Architecture and evidence boundary

`HostBridge` validates and routes; `HostServices` owns shared proxies and scheduling. `DeviceSources` owns fixed root/layer/child addresses and continuity; one `ParameterModule` owns continuous source-specific parameter data and the shared binding/request. Other domain modules retain their own observations. Grid separates RPC/target guards, the exact-version reflective adapter, bounded model serialization, scalar/panel/topology writers and shared lifecycle admission. The boolean-panel writer reuses parameter context/serialization while retaining its distinct setter and coupled scalar checks. Insertion adds a narrow public boundary and lazy unnamed-package loader subclass, not another transport or transaction layer. Python separates strict schemas, one catalog, transport, CLI and MCP. No project mirror, planner, workflow DSL, automatic GUI fallback, implicit retry or generic transaction layer is introduced.

`ModulatorModule` separately owns root-device read RPCs and bounded serialization through `BoundedJson`; `ModulatorSnapshotReader` owns nonloading primary/direct inventory and exact-value guards. `DeviceSources` supplies the existing root authority and an invalidatable root-read ticket: controller capture/final delivery recheck public observations, while native callbacks use the published epoch/deadline without Controller API getters. Results cross queues as immutable bounded JSON, not native references. This does not change layer cold-index/discontinuity rules or public direct-parameter bindings.

`Bitwig614Runtime` is lazy/shared per `HostServices`, centralizing exact version, loaded CodeSource/hash/ClassLoader, descriptor checks and document dispatch while keeping domain errors and bindings independent. `NativeDeviceTarget`/`Bitwig614DeviceTargetAccess` share native target/track-alias/UUID corroboration; `NativeReadContext`/`Bitwig614ReadContextAccess` share lifecycle and owning-context checks. Initialization, root equality and default Dt remain observations rather than new read gates. `Bitwig614StringPanelAccess` is the shared exact native string-panel reader, not a setter. Grid retains its own edit-context, writers, quarantine and asynchronous cleanup; modulator reads do not couple to those write paths.

Offline client tests, simulated-host Java tests, transported MCP fixtures, native read-only preflight and independent musical/UI/persistence E2E are different evidence layers. Passing one does not promote another to passed. Native preflight verifies exact loopback socket ownership (including Linux IPv4-mapped TCP6 entries); project-name equality alone cannot establish which full project path is loaded.
