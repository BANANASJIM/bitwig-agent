# Grid and music recipe boundaries

Use this reference before native Grid edits or the public scratch-music recipe. It does not grant permission to operate a DAW. Exact schemas remain in live tool discovery and the version-matched public [protocol](https://github.com/BANANASJIM/bitwig-agent/blob/main/PROTOCOL.md).

## Compatibility and discovery

Version **`0.3.x`** maps private Grid/modulator access to **Bitwig Studio 6.1.4 / API 25** and the exact supported **loaded host-JAR** SHA-256; the older `0.1.2` release retains its 6.1.3 gate. Linux native evidence remains bounded to exercised cases. Another JAR on disk, successful Python installation or a passing package smoke does not extend this private binding's compatibility. Public SDK operations and separately authorized GUI work have different scopes; verify each independently. Do not bypass a mismatch. See [versions and sources](version-and-sources.md).

Call `grid.capabilities` (compact by default; `detail:"full"`) and inspect separate read/write availability and topology admission. `grid.catalog` matches names only (no categories) but loosely: case/space/hyphen-insensitive, every word must match, a miss returns `suggestions`; search "low pass", not "Filter". Availability means a binding is present, not that every module/type has native acceptance. Start a structure/layout/wiring/name inspection with a small `grid.get` page, `includeParameters=false`, and an explicit current device target. Inspect `window.complete` and unsupported coverage; top-level completeness has additional requirements. Stored cables are not proof of the active signal graph.

Discover exact module instance IDs, ports and controls (`grid.get` `moduleIds` returns only those modules' parameters; `diagnostics:true` restores native class/path metadata); catalog type IDs are not module instance IDs. Module/modulator UUIDs may change on reopen. Unknown native children remain unsupported. Grid-family string panels lack a real fixture; Macro-modulator observations do not establish that coverage. Modulator inventory and exact string-panel values are read-only, not loading/mapping/editing support.

## Guarded raw changes

For a supported parameter, take `expectedKind`/`expectedValue` from a recent `grid.get` row (`grid.parameters.get` is only for a fresh single value); stale ones are refused as an error before dispatch. `writes` batches one device's parameters: all checks first, then in order, stopping at the first non-success entry (later entries `not_applied`/`not_reached`; results include `display`). Numeric raw values are not normalized/display values or automatically seconds, hertz or decibels. Enum values are actual option values, not their list positions. No guessing or clamping. A `display` write (see below) is the only display conversion.

String panels (`kind:"string"`, e.g. Comment text) are written with `expectedKind:"string"` and string `expectedValue`/`value` (at most 1024 UTF-16 units, verbatim); a Label module shows the module name, so use `grid.modules.rename`. Step tables (`kind:"steps"`: Steps, Pitches, Gates, Probabilities, Accents) are written with `expectedKind:"steps"`, `expectedValues` (the live entries from step 0 as read by `grid.get`, normally the first `stepCount`; its length is the CAS window) and `values` (up to that many entries, within -128..128, from step 0; the rest is kept); one write per table, batchable (a transition matrix is one batch of Probabilities rows). Observed natively: Pitches in Grid pitch units, Gates 1/0, Accents 0/0.5/1, Probabilities 0..1. Device voicing is `grid.voicing.get`/`grid.voicing.set` (Poly Grid only: `voices`, `voiceStacking`, `monoMode` true_mono|digi_mono, retrigger, priority, ...), with `expected`/`set` CAS. Boolean-panel changes are a separate guarded operation and may coerce a coupled scalar; do not flatten those relationships into a guessed scalar write. Custom-name CAS uses raw `customName`, not the effective display name. Topology writers have their own lifecycle/quarantine checks and return diffs (`modulesAdded`, `connectionsChanged` for native repair; `graph:"full"` for the whole graph): wire an inserted module from `modulesAdded`, no re-read. `grid.connections.set` `connections` inserts a module into a chain in one call, stopping at a failure or a native-repair `mismatch`, with one diff; only a native setter failure latches the topology quarantine (`unknown`). Do not assume a readable graph authorizes insert/move/delete/rename/cable edits.

Native context, license/property and undo observations do not constitute user permission, a global lock or engine acknowledgement. Check applicable stopped/nonrecording/nonautomation conditions and current ownership, and stop on any `unknown` outcome. Native undo-aware dispatch does not promise grouping, rollback or saved persistence.

## Fast patch building

`grid.catalog` (or `typeName` directly) → one batch `grid.modules.insert` (`modules`) → one batch `grid.connections.set` → one batch `grid.parameters.set` by `display`. Details in [PROTOCOL](https://github.com/BANANASJIM/bitwig-agent/blob/main/PROTOCOL.md).

**Read the docs first:** before using an unfamiliar module run `bitwig-agent-rpc grid.describe type="<module>"` (or `query="<keywords>"`): Bitwig's own description and per-port/parameter notes, read offline from the local install. Check `rawEntries` when a port has no `description`.

**Patch as code:** for more than a handful of modules use `grid.apply` (client-side; `bitwig-agent-rpc grid.apply spec=@patch.json`): `modules:[{name,type,x,y,params}]` + `connections:[{from:"name.OUT",to:"name.IN"}]`, `dryRun` first. Name is the unique `customName` identity, so re-applying is a diff and repeated blocks stay identical. `params` take raw values, `{label}` (enum) or `{display}`. Step arrays: `params:{DATA:{steps:[1,0,0.5]}}` on Steps/Pitches/Gates/Probabilities/Accents (id from the live `kind:"steps"` row of `grid.get`; first entries written, rest unchanged; equal arrays skipped; block arg may be a list via `{steps:"${row}"}`). Poly Grid voicing: top-level `voicing:{voices:8,voiceStacking:1,monoMode:"true_mono"}` writes only differing fields; Note/FX Grid is refused before any write. **Grid pitch units** (defined here and in the apply notes): 0 = MIDI 60, 1 semitone = 1/120, 1 octave = 0.1; Pitches steps and oscillator PITCH_IN use them (PITCH_IN is scaled by PITCH_MOD).

**Preflight:** `dryRun` is read-only and returns `warnings` (ignored PHASE_IN cable while DEVICE_PHASE is on, filter KEYTRACK in a Poly Grid, unconnected or dead-end modules, PITCH_MOD 0) and `wouldFail` (transport playing/recording, host-converted display writes, unreachable target). Unknown parameter/port errors list the valid ids. `namespace`+`prune` removes stale owned modules/cables only. One spec per Grid device (sections as prefixes inside it); two specs sharing a namespace with prune delete each other's modules. `{display}` only for hertz/percent/decibel params whose default display is nonzero, else write the raw value; time params of envelopes/Logic Delay/Gate Length/Lag etc. take `{display:"3 ms"}` or `"0.5 s"` (client converts to raw; others, e.g. Long Delay TIME, need raw: cbrt(seconds) for AD/ADSR, log10(seconds) for Logic Delay/Gate Length). Repeated sub-patches: `blocks:{voice:{params:{atk:0.2},modules:[{name:"osc",type,x,y,params:{ATTACK:"${atk}"}}],connections:[{from:"osc.OUT",to:"env.IN"}]}}` + `instances:[{block:"voice",prefix:"D1: ",dy:12,args:{atk:0.1}}]`; local names inside the block, expanded names (`"D1: osc.OUT"`) for cables to the rest; no nesting; `dryRun` shows the expansion. It stops at the first error/unknown/partial (see `failure`, `notReached`); do not retry blindly, inspect then re-apply.

**Work on an existing patch:** `grid.export` returns a `grid.apply` spec of the live device (names, types, positions, changed params, cables, voicing); edit it and apply it back (unchanged = no writes). `grid.graph` reads the same names (modules + `from`/`to` cables) without UUID joins. In a spec for one section use `external:["X: sum"]` to wire into modules you do not declare; `prune` never cuts inputs of declared modules outside `namespace` unless `allowOutsideDisconnect:true`.

**Macro knobs:** `devices.remote.define` gives the device a named Remote Controls page whose knobs drive chosen scalar Grid parameters, e.g. `pageName:"Macros"`, `slots:[{moduleName:"Mx: darkness", parameterId:"VALUE", label:"darkness"}, ...]` (up to 8, slot k = entry k, null = empty) over Value modules. `mode:"replace"` re-applies idempotently (only differing slots change); `devices.remote.deletePage` removes it. The result gives `pageIndex` for `devices.remote.page`/`devices.remote.set`. Pages go in the device's preset-page list (what the UI's Add New Page creates; device pages cannot hold Grid module parameters); each step is its own Undo step.

**See the layout:** `grid.render` (client-side, read-only; `outPath` absolute, `format` svg|png, `overwrite`, `namespace`, `scale`) draws the device and returns a summary: `overlaps`, `unconnected`, `sections` (by `"H: "` prefix, with bounding boxes), `density`, `categories`. Read the summary to judge layout; open the image only when you can view it. Render after each `grid.apply` while tuning positions.

**Check silent drops:** after Grid topology writes, run `host.diagnostics` (a real `grid.apply` returns `diagnosticsMarker`: pass it as `sinceMarker`; `grid_rejected` bursts while a build is still inserting are expected, only events after the build matter) and look for `grid_rejected` (a device missing a required in-port is dropped from the audio network and just goes silent; the API shows nothing). Pass the previous call's `marker` as `sinceMarker` to see only what your write caused. Modal dialogs are not in the log: take a screenshot.

- `typeName` must match exactly one catalog name (case/space/hyphen-insensitive); zero or several reject with candidates. Batch insert stops at the first failure or before the deadline (partial); later inserts can push earlier modules right, so use the reported final positions.
- `display` writes (`Hz`/`kHz`, `%`, `dB`) work only after per-parameter calibration, else `unsupported_unit` (a Drive with dB display but linear raw was refused natively). Pitch-like parameters are MIDI-note raw (84 = 1.05 kHz). `displayMismatch` is reported, never corrected.

## Device modulators for controls without ports

Many Grid controls have no input port (envelope times, Gates STEPS, Chance PROBABILITY, oscillator TIMBRE, Distortion DRIVE, pulse width). Vary them with a device modulator instead of more modules:

1. `modulators.catalog query="random"` (offline) picks a type; `modulators.describe type=Random` explains its controls.
2. `modulators.get parent=…` gives the current `count`; `modulators.insert expectedCount=<count> typeName=Random` returns the new `modulatorId` with its `outputs` and `parameters`.
3. `modulators.map modulatorId=… target={moduleId: <AD from grid.get>, parameterId: DECAY} expectedAmount=null amount=0.5`; the result's `mapping` is the readback. Change the amount later with `expectedAmount=0.5 amount=0.3`; remove it with `modulators.unmap`.
4. Shape the modulator with `modulators.parameters.set` (raw CAS, like `grid.parameters.set`). Polarity is a modulator parameter, not a mapping option.

Insert, delete, map and unmap need a stopped transport; `modulators.parameters.set` works while playing. Recording or automation write on blocks all of them. An `unknown` outcome means inspect `modulators.get`, never repeat. Native acceptance of these edits is not yet recorded in VERIFICATION.

## Scratch recipe: explicit agent workflow

The public [usage guide](https://github.com/BANANASJIM/bitwig-agent/blob/main/USAGE.md#make-grid-instruments-without-preset-files) and [recipe source](https://github.com/BANANASJIM/bitwig-agent/blob/main/examples/grid_music.py) contain the complete source-checkout commands. The wheel does not install the recipe as a tool, and this copied skill does not bundle it. Do not invent a missing executable or download/run it without permission.

The recipe requires an explicitly named disposable project, fresh safety observations, a new evidence directory and explicit `--allow-write`. It creates two muted/disarmed instrument tracks and eight beats of pluck notes/pad chords. In `--from-scratch` mode it discovers the factory Poly Grid/catalog and constructs Union → ADSR → Audio Out without caller-supplied preset files. Fixed Analog ADSR settings are bounded native-observed calibrations, not a general physical-unit conversion. Alternatively omit `--from-scratch` and provide **both** host-authored pluck and pad presets; mixed/incomplete modes reject, and presets must never be fabricated.

Only `report.json`'s `createdTracks` and their slot-0 clips/devices are owned outputs; existing tracks are not edited. A project name is not full-path identity or an atomic lock. Use a complete ungrouped track window. The recipe retains full responses and partial ownership, stops on an `unknown` outcome, and does not play, render, save, undo or retry. Do not rerun it after uncertainty. A null note count is unverified, not empty.

### Pad voice count

The original factory Pad was **Mono / 1 voice** and four-note chords need polyphony. Set the voice count through the API: `grid.voicing.set` (CAS with `expected`/`set`, Poly Grid only) or `grid.apply` with `voicing:{voices:8}`; read it back with `grid.voicing.get` (the `editContext` observation needs `detail:"full"`). Eight voices permit overlapping releases. The recipe script itself still reports a GUI step in its stdout `next`; that step is only needed when you drive the recipe, not for a patch built with `grid.apply`.

The recipe uses Pad Triangle Level **0.125 per voice** for headroom and Pluck Level **1.0**. The original Mono case lacked three chord fundamentals; a later corrected case does not retroactively pass it, uniquely isolate simultaneous voice/level changes, or establish whole-recipe persistence/listening acceptance.

### Render and completion boundaries

Graph/control/MIDI readback establishes bounded authoring observations, not sound or persistence. Playback, bounce, save and reopen are separate authorized actions. For GUI Bounce, select the actual owned Launcher clip and inspect its context before invoking **Bounce...**; an Action/selection response does not prove the dialog target or result.

For looping bounces inspect the full audio-event/file extent, initial Start and repeating loop region separately: they can differ. An earlier maximum-seven-second criterion failed; observing a sixteen-beat event with an eight-beat loop does not change that failure or prove a universal generation rule. No automatic rendering/saving workflow is supplied. Use the public [verification limits](https://github.com/BANANASJIM/bitwig-agent/blob/main/VERIFICATION.md#coverage-limits-and-unresolved-results) rather than promoting later corrections into blanket native acceptance.
